# 电脑配件价格监控系统

自动抓取京东、什么值得买等平台的电脑配件到手价，持久化历史价格，通过 ECharts 可视化看板展示**今日涨跌排行、价格走势、跨平台对比、历史最低/最高价区间**。

## 目录结构

```
pc-price-monitor/
├── data/
│   ├── catalog.json          # 配件清单（85款型号 × 京东/什么值得买 = 170 SKU）
│   ├── prices/               # 历史价格（按日期命名，每日一个文件，追加不覆盖）
│   │   └── 2026-09-09.json
│   ├── latest.json           # 最新价格快照（合并当天所有记录，覆盖全量 SKU）
│   └── tmp/                  # 抓取批次暂存（finalize 后清空）
├── scripts/
│   ├── browser_fetch.py      # 【主抓取器】基于浏览器自动化，抓京东+什么值得买
│   ├── fetch_prices.py       # 旧版 requests 直连脚本（当前网络下大部分通道不可用，保留作参考）
│   ├── run.bat               # 一键运行（调用旧版脚本，主环境建议改用 browser_fetch.py）
│   ├── generate_catalog.py   # 清单生成脚本
│   ├── append_catalog.py     # 追加型号到清单
│   ├── append_new_models.py  # 追加热门新型号（9800X3D 等）
│   └── validate.py / verify_catalog.py / fix_platform.py
├── dashboard/
│   ├── index.html            # ECharts 可视化看板（四大模块）
│   └── data.js               # 自动生成的内嵌数据文件（无需服务器）
└── README.md / DATA_SPEC.md
```

## 运行方式

### 定时自动更新（已配置，无需手动）

系统已创建定时任务：**每天 09:00 和 21:00** 自动抓取全量清单并刷新看板。任务在用户本地环境运行，复用当前浏览器登录态。

### 手动更新

在本会话里直接说"更新配件价格"即可，由助手执行浏览器自动化抓取（`browser_fetch.py` 的 `run_batch` / `finalize_batch`）。

> 不建议双击 `run.bat`：它调用旧版 requests 直连脚本，在多数住宅/办公网络下京东接口不可达、SMZDM 被 WAF 拦截，抓不到价格。

### 查看看板

用浏览器打开 `dashboard/index.html`（双击即可），刷新页面（F5）查看最新数据。

## 抓取通道（实测结论）

| 平台 | 通道 | 状态 | 说明 |
|------|------|------|------|
| 什么值得买 | 搜索页 `search.smzdm.com/?c=home&s=<型号>&v=b` | ✅ 主力通道 | 浏览器自动化可稳定访问，无需登录；聚合京东/拼多多/天猫等渠道到手价；同时收集该型号**全部历史好价点**（价格+时间+渠道）用于历史最低/最高 |
| 京东 | 商品页 `item.m.jd.com/product/<sku>.html` | ⚠️ 限流严重 | 页面 script 内 `priceFloor.ext.jdPrice` 为明文到手价；约每 10~15 分钟窗口仅能成功 2 个，作手动补漏通道 |
| 京东 | 搜索页 `search.jd.com/Search?keyword=<型号>` | ⚠️ 频控严格 | 登录后价格可见；连续约 5~8 次触发"访问频繁"冷却，作低频补充通道（无 sku 的新型号走此通道） |
| 京东 | p.3.cn 价格接口 / 其他接口 | ❌ 不可用 | 当前网络下连接超时/风控，勿依赖 |

**数据覆盖策略**：什么值得买为主力（覆盖有"好价爆料"的型号），京东限流下逐轮补充；无数据的型号标记 `status="failed"`，随多轮更新累积覆盖。

## 看板功能（四大模块）

### 模块一：今日涨跌排行
- 对比**最近两次抓取**的同 SKU 价格变化，按涨跌幅降序
- 横向柱状图 + 明细表格（上次价/本次价/涨跌额/涨跌幅）

### 模块二：价格走势曲线
- 品类 + 型号二级筛选，近7天/近30天切换
- 各平台多色折线图

### 模块三：跨平台价格对比
- 选中型号后对比各平台当前到手价，自动标注最低价（橙色高亮 + ★）

### 模块四：历史最低 / 最高价区间（v2 新增）
- 每个型号一条"历史最低→历史最高"区间条 + 当前价圆点
- 明细表：历史最低（价格/时间/来源）、历史最高、距最低溢价%、历史点数
- 数据来源：① SMZDM 该型号全部历史好价点（offers 字段）；② 系统每日两次快照的本地积累
- 支持按品类筛选；区间条越宽代表价格波动越大，点数越多数据越可信

## 常见问题

- **Q: 京东很多型号显示 failed/暂无数据？** A: 京东限流严重，属正常现象；定时任务每轮会尝试补充，SMZDM 为主力数据源。
- **Q: 定时任务需要保持京东登录吗？** A: SMZDM 不需要登录。京东补充通道需要浏览器登录态，若登录过期，该轮京东部分会跳过并提示，不影响 SMZDM 数据。
- **Q: 如何扩展型号？** A: 编辑 `data/catalog.json`（每条 = 型号×平台），或让助手运行 `append_new_models.py` 追加热门型号。

## 数据格式

详见 `DATA_SPEC.md`。核心要点：
- `data/prices/YYYY-MM-DD.json`：数组，每次抓取追加一条记录（`fetch_time` + `items`），同一天多次抓取不覆盖
- `data/latest.json`：**合并**当天全部记录，每个 SKU 取最新一次抓取结果，始终覆盖全量清单
- `dashboard/data.js`：自动生成 `window.PRICE_DATA`（latest + history），看板直接引用
- 每条 item 含：`id/category/model/platform/price/price_label/original_price/status/note`；SMZDM 条目含 `offers`（该型号历史好价点数组：`{price, shop, time, title}`）
